# E-Complaint — แบบฟอร์มประชาชน (Google Apps Script)

## สถานะ
ซอร์สโค้ด Frontend และ Backend พร้อมสำหรับการตั้งค่า/ทดสอบ **ยังไม่ได้เผยแพร่เป็นระบบรับเรื่องจริง**.
อย่าเชื่อมการ์ดบน GitHub Pages มายัง Web App จนกว่าจะทดสอบและยืนยันสิทธิ์ข้อมูลส่วนบุคคลครบถ้วน.

การตรวจสอบสิทธิ์ Google Drive เมื่อ 16 พ.ย. 2569 พบว่า **โฟลเดอร์ทั้งสาม และบรรพบุรุษใน Drive** 
`1LVXLL0F7Q2RUvwyyVF0PM25TlKX8w8FW` และ `1dtzmMhlP1dCgt7fLgFgCQcs6MEsNOHzo` มีสิทธิ์ Anyone with the link (Reader).
เนื่องจากข้อมูลร้องเรียนมีข้อมูลส่วนบุคคล/บัตรประชาชน/หลักฐาน ระบบจึงตรวจว่าโฟลเดอร์ทั้งหมดและทุกบรรพบุรุษเป็น PRIVATE ก่อนรับข้อมูล; หากพบสิทธิ์สาธารณะจะปฏิเสธคำขอและไม่สร้างโฟลเดอร์ใหม่.
**ห้ามแก้สิทธิ์ของโฟลเดอร์ระดับบนโดยไม่ตรวจผลกระทบกับเว็บไซต์และข้อมูลอื่นก่อน**. อาจต้องจัดโครงสร้างพื้นที่จัดเก็บส่วนตัวใหม่พร้อมย้ายโฟลเดอร์เป้าหมายโดยผู้ดูแลระบบที่มีสิทธิ์.

## ไฟล์
- `Code.gs` — Backend Apps Script; ตรวจบัญชี Google ID token, สร้างโฟลเดอร์ต่อเรื่อง, รับไฟล์แบบจำกัดประเภท/ขนาด, บันทึก Sheets, ปิดรายการ
- `Intake.html` — Frontend HTMLService; รองรับมือถือ, Google Login, ข้อมูลร้องเรียน, รูปภาพ 1–4, วิดีโอ MP4, และกรณีประสงค์รับสินบนฯ ต้องแนบ PDF 4 รายการ

## วิธีตั้งค่า (เจ้าหน้าที่ผู้รับผิดชอบ)
1. จัดพื้นที่เก็บข้อมูลที่ไม่เปิดเผยสาธารณะก่อน ตรวจสิทธิ์ของโฟลเดอร์หลัก/ย่อยและทุกโฟลเดอร์ระดับบน; การแก้สิทธิ์ปัจจุบันต้องพิจารณาผลกระทบก่อน.
2. ที่ Google Apps Script สร้างโปรเจกต์ใหม่ (บัญชีหน่วยงานซึ่งเป็นเจ้าของพื้นที่จัดเก็บ) แล้วสร้างไฟล์ `Code.gs` และ `Intake.html` โดยคัดลอกต้นฉบับในโฟลเดอร์นี้; ไม่ทับระบบ E-Complaint ปัจจุบัน.
3. สร้าง Google OAuth Client ID (Web Application) สำหรับ Google Identity Services และตั้งค่า origins ที่ Google อนุญาตตาม URL ที่ใช้งานจริง แล้วแก้ค่า `GOOGLE_CLIENT_ID` ใน `Code.gs`. ให้ตรวจว่าการเข้าสู่ระบบใช้งานได้จริงใน Web App.
4. ตรวจ folder IDs ใน `INTAKE` ให้ตรงกับโครงสร้างที่อนุญาต แล้วเรียก `setupIntake()` ใน Editor เพื่อสร้างทะเบียน Google Sheets.
5. Deploy > New deployment > Web app, Execute as: Me (เจ้าของที่ได้รับอนุญาต), Who has access: Anyone เพื่อให้ประชาชนที่เข้าสู่ระบบ Google ใช้ได้. Backend ตรวจ Google ID token อีกชั้นทุกคำสั่ง. ทดสอบบัญชีประชาชนและกรณีไม่มีสิทธิ์ก่อนเปิดรับจริง.
6. รับ URL Web App `.../exec` จากการ deploy แล้วทดสอบ `?intent=reward` และ `?intent=no-reward` แบบ end-to-end ด้วยข้อมูลทดสอบที่ไม่ใช่ข้อมูลจริง ตรวจ folder, Sheet และเอกสารทั้ง 4 PDF.
7. หลังผลทดสอบผ่าน จึงอัปเดตสองการ์ดย่อยใน `index.html` ของ GitHub Pages ให้เปิด URL ตาม intent โดยใช้ `target="_blank" rel="noopener noreferrer"`. อย่าผูกสองการ์ดกับฟอร์มเดียวโดยไม่มีตัวแปรแยกประเภท.

## ข้อจำกัด
- ยังไม่มี deployment URL จริงหรือ Google OAuth Client ID ที่ใช้งานได้ในโปรเจกต์นี้ จึงยังเชื่อมการ์ดหน้าหลักกับระบบใหม่นี้ไม่ได้.
- Backend ใหม่เก็บทะเบียนใน Sheets แยกจากระบบติดตามสถานะ E-Complaint ปัจจุบัน; ยังไม่รวมเข้ากับ API ติดตามเดิม.
- แอปจำกัดรูปภาพ 5 MB/ภาพ, วิดีโอ MP4 12 MB และ PDF 10 MB/เอกสาร; ควรทดสอบโควตา Apps Script และความเร็วบนมือถือ.
- แบบ น.จ.1 / แบบคำขอรับเงินผ่านธนาคาร / สำเนาบัตรประชาชน / สำเนา Bookbank เป็นเอกสารที่จำเป็นเฉพาะกรณีประสงค์รับเงินสินบนนำจับ ตามข้อกำหนดการทำงานเดิม.
- ก่อนใช้งานจริงต้องมีประกาศความเป็นส่วนตัวของหน่วยงาน การเก็บรักษาและลบข้อมูล การจำกัดสิทธิ์เจ้าหน้าที่ และกระบวนการกู้คืนในกรณีอัปโหลดไฟล์บางส่วนไม่สำเร็จ.

## การทดสอบสำคัญ
- ทุกการยื่นเรื่องสร้างโฟลเดอร์คนละแห่งและอยู่ในสาขาที่ตรงกับ intent.
- เปิดด้วยบัญชีผู้ใช้อื่นต้องเข้าถึง case เดิมไม่ได้.
- เมื่อโฟลเดอร์หรือโฟลเดอร์ระดับบนใด ๆ เป็น public ต้องไม่สร้างเรื่องใหม่.
- ปฏิเสธไฟล์เกินขนาด/รูปแบบไม่ถูกต้องและเอกสาร PDF ที่ขาดหาย.
- ยื่นซ้ำ nonce เดิมต้องไม่สร้างโฟลเดอร์ซ้ำ.
- กด Back/Reload แล้วไม่ทำให้คำร้องซ้ำจากการคลิกโดยไม่ตั้งใจ.
