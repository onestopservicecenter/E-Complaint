## โฟลเดอร์รายวันและรายงานจำนวนคำร้อง (ปรับล่าสุด)

```

├── ประสงค์ขอรับเงินสินบนนำจับ/

│       └── NPT-YYYYMMDD-XXXXXXXX/

│           └── evidence-N.ext
└── ไม่ประสงค์ขอรับเงินสินบนนำจับ/
    └── YYYY-MM-DD/
        └── NPT-YYYYMMDD-XXXXXXXX/
            ├── คำร้อง.json
            └── image-N.ext
```
- ชื่อโฟลเดอร์วันที่อ้างอิง **วันที่เริ่มยื่นตามเขตเวลา Asia/Bangkok**; หากประชาชนเริ่มก่อนเที่ยงคืนและส่งสำเร็จหลังเที่ยงคืน โฟลเดอร์ยังอยู่ในวันเริ่มเรื่อง

- `staffDailySummary({idToken,date:'YYYY-MM-DD'})` แสดงจำนวนคำร้องที่ส่งสำเร็จตามวัน: ทั้งหมด / ประสงค์ขอรับเงินสินบนนำจับ / ไม่ประสงค์ขอรับเงินสินบนนำจับ; ไม่คืนข้อมูลบุคคลหรือไฟล์

## บันทึกการใช้งาน (Audit Log) และ PDPA
Backend `Code.gs` มีแท็บ `AuditLog` ในทะเบียน Google Sheets ที่เจ้าของระบบสร้างด้วย `setupIntake()` (เรียกอีกครั้งได้หากทะเบียนมีอยู่แล้ว). เขียน Audit Log ฝั่ง Server โดยใช้บัญชี Google ที่ตรวจ ID token แล้วเท่านั้น:
- `CASE_DRAFT_CREATED` — เริ่มเรื่องใหม่
- `CASE_SUBMITTED` — ส่งเรื่องสำเร็จ
- `CITIZEN_STATUS_VIEW` — ผู้ร้องตรวจสถานะ
- `STAFF_CASE_LIST` — เจ้าหน้าที่เปิดรายการ
- `STAFF_CASE_VIEW` — เจ้าหน้าที่เปิดรายละเอียดคำร้อง
- `STAFF_EVIDENCE_DOWNLOAD` — เจ้าหน้าที่เรียกหลักฐาน

คอลัมน์: เวลาบันทึก / การกระทำ / เลขรับเรื่อง / อีเมลบัญชีผู้กระทำที่ยืนยันแล้ว / บทบาท / ผลลัพธ์. **ไม่เก็บ** Google ID token, รหัสผ่าน, เลขบัตรประชาชน, ข้อความร้องเรียน, หรือไฟล์หลักฐานใน Audit Log. อีเมลผู้ร้องยังถูกจัดเก็บในทะเบียนคำร้องและไฟล์คำร้องที่แยกจาก Log เพื่อใช้ผูกข้อมูลผู้ยื่น.

**การติดต่อกลับ:** ให้ใช้บัญชี Google ที่ผ่านการตรวจตัวตนเป็นช่องทางอ้างอิงหลัก; อีเมลสำรองจากช่องกรอกเป็นข้อมูลที่ผู้ใช้พิมพ์เองและยังไม่ได้ยืนยันความเป็นเจ้าของ. ห้ามส่งรายละเอียดคำร้อง ชื่อคู่กรณี เลขบัตร หรือไฟล์แนบไปกับอีเมลแจ้งเตือน. ออกแบบให้ส่งเพียงเลขรับเรื่องและแจ้งให้ผู้ร้องเข้าสู่ระบบเพื่อตรวจผล โดยตรวจสิทธิ์อีกครั้ง. **ยังไม่ได้เปิดฟังก์ชันส่งอีเมลและยังไม่ผ่านการทดสอบ**.

ก่อนใช้งานจริง ต้องได้รับการอนุมัติจากผู้ควบคุมข้อมูลส่วนบุคคลเกี่ยวกับประกาศความเป็นส่วนตัว วัตถุประสงค์/ฐานกฎหมายในการใช้ข้อมูล ระยะเวลาจัดเก็บ การลบข้อมูล การคุ้มครองสิทธิของเจ้าของข้อมูล ผู้มีสิทธิ์อ่าน Log และการแจ้งเหตุละเมิดข้อมูลตามข้อเท็จจริงและกฎหมายที่ใช้บังคับ. Audit Log ปัจจุบันไม่ใช่ระบบป้องกันการแก้ไขแบบ tamper-proof และยังไม่ได้ทำระบบตรวจจับการเข้าถึงที่ถูกปฏิเสธหรือออกแบบการเก็บ Log แบบ immutable. ห้ามถือว่าผ่านการตรวจ PDPA แล้วจากการเพิ่มโค้ดนี้เพียงอย่างเดียว.

## สิ่งที่ผู้ดูแลระบบต้องตั้งค่าเพื่อทดสอบจริง
1. ยืนยันกับหน่วยงานว่าบัญชีเจ้าของพื้นที่เก็บข้อมูลใหม่เหมาะสมหรือไม่ และใช้บัญชีที่มีสิทธิ์จริงในการ Deploy. โฟลเดอร์ชุดใหม่ตรวจ metadata แล้วว่าไม่แชร์สาธารณะ
2. สร้าง Google Apps Script Project ในบัญชีหน่วยงาน และสร้างไฟล์ใน Apps Script ให้ตรงชื่อและเนื้อหา `Code.gs`, `Reward.html`, `Intake.html`, `Staff.html`. โค้ดใน GitHub ยังไม่ใช่ Web App ที่ Deploy แล้ว
3. สร้าง Google OAuth Web Client ID สำหรับ Google Identity Services ที่ใช้งานกับ URL ของ Web App นี้ได้จริง แล้วกรอก `GOOGLE_CLIENT_ID` ใน `Code.gs`
4. กำหนด `STAFF_EMAILS` ใน Script Properties เป็นอีเมลเจ้าหน้าที่ที่ได้รับอนุมัติ คั่นด้วย comma โดยห้ามเปิดสิทธิ์แก่บัญชีอื่น
5. รัน `setupIntake()` หลังตรวจ Google Drive และ ID Client; คำสั่งสร้าง Google Sheets ทะเบียนคำร้อง
6. Deploy เป็น Web App ภายใต้เจ้าของพื้นที่จัดเก็บ (Execute as Me) โดยตรวจทานสิทธิ์การเข้าถึงและบทบาทก่อนเปิดบริการสาธารณะ
7. ทดสอบ `/exec?intent=reward`, `/exec?intent=no-reward`, และ `/exec?view=staff` ด้วยบัญชีทดสอบประชาชนและเจ้าหน้าที่ที่ได้รับอนุญาต ทั้งกรณีมี/ไม่มีสิทธิ์ การส่งซ้ำ การอัปโหลดไฟล์ และคำร้องที่ยังไม่สมบูรณ์
8. เมื่อผ่านการทดสอบกับไฟล์จำลองและตรวจสอบการรักษาความลับแล้ว จึงเชื่อมการ์ดใน `index.html` กับลิงก์ Web App ปลายทางจริง `target="_blank"`

## สิ่งที่ยังไม่ได้เสร็จ
- ยังไม่มี Google OAuth Client ID, อีเมลเจ้าหน้าที่ที่อนุมัติ, Script Project/Deployment URL. โฟลเดอร์ส่วนตัวชุดใหม่สร้างแล้วแต่ต้องยืนยันบัญชีเจ้าของที่หน่วยงานอนุมัติ
- ยังไม่ได้ทดลอง Google Identity Services ภายใน Apps Script HTML Service หรือการทำงาน end-to-end (จึงไม่ยืนยันว่าใช้งานจริงสำเร็จ)
- หน้า Dashboard ใหม่นี้เป็นระบบ *ดูรายการและหลักฐานแบบ Read-only* ยังไม่ได้ผสานระบบเจ้าหน้าที่ E-Complaint เก่า/สิทธิ์ Admin/Staff หรือประวัติการดำเนินการ/สถานะการตอบกลับ
- ระบบเก็บไฟล์ไว้ใน Google Drive ภายใต้บัญชีบริการ แม้เจ้าหน้าที่จะทำงานผ่านเว็บ ก็ไม่สามารถป้องกันผู้ดูแลระบบ Google Drive ที่มีสิทธิ์โดยชอบไม่ให้เข้า Drive ได้
- จำเป็นต้องพิจารณาและรับรองข้อความข้อตกลงตามกฎหมาย นโยบาย PDPA สิทธิ์ผู้เข้าถึง การเก็บรักษาและลบข้อมูล การจัดการสำเนาบัตรประชาชน และขั้นตอนตอบกลับก่อนใช้งานจริง
